# Plan: TL-5 Tasks #123 and #124 — Catalog Export JSON + mirror.toml at Build Time

**Owner:** TL-5
**Issues:** #123 (closes #38, #39, #40), #124 (closes #41)
**Branch:** feat/task-123-124-catalog-exports

## Objective

Generate `/exports/catalog.json`, `/exports/by-class.json`, `/exports/by-lifecycle.json`, and `/mirror.toml` into `web/dist/` at Astro build time, with zero-atom-safe empty-structure outputs.

## Alternatives Table

| Alternative | Pros | Cons | Verdict |
|---|---|---|---|
| Astro integration (`astro:build:done` hook) | Native to Astro, runs after all pages are rendered, output goes directly into dist | Requires `.ts` import in `.mjs` config; Astro supports this with Vite | **Chosen** |
| Separate `prebuild` npm script | Simple, no Astro coupling | Output must be pre-placed in `public/`, gets copied to dist — double write; harder to target dist directly | Rejected |
| Static files committed to `public/` | Zero build overhead | Stale data, not generated, defeats the purpose | Rejected |

## Scope

**Create:**
- `web/src/scripts/generate-exports.ts` — catalog builder and TOML generator

**Modify:**
- `web/astro.config.mjs` — add `catalog-exports` integration with `astro:build:done` hook

**Generated outputs (not committed):**
- `web/dist/exports/catalog.json`
- `web/dist/exports/by-class.json`
- `web/dist/exports/by-lifecycle.json`
- `web/dist/mirror.toml`

## Approach

1. Write `generate-exports.ts`:
   - `buildCatalog()`: scan `../compositions/` for `.toml` files in class subdirectories; return flat `AtomEntry[]`
   - `writeExports(outDir)`: build by-class and by-lifecycle groupings; write 3 JSON files + mirror.toml
   - `buildMirrorToml()`: emit minimal valid TOML from ATOMS.yml metadata (name, domain, federation)
   - Zero-atom case: `catalog.json = []`, `by-class.json = {}`, `by-lifecycle.json = {}`

2. Add Astro integration to `astro.config.mjs`:
   - Import `writeExports` from the script
   - Hook `astro:build:done` → `writeExports(dir.pathname)`
   - Preserve existing `site` and `output` config

3. Verify `cd web && npm run check && npm run build` both pass
4. Verify dist outputs exist and are valid

## Testing Strategy

  7. Assert mirror.toml contains "schema-atoms"

## Risk Assessment

- **Astro `.ts` import in `.mjs`**: Astro's Vite pipeline handles TypeScript in config imports natively. Low risk.
- **`compositions/` directory structure**: 24 class dirs currently contain only `.gitkeep`. Script must handle `readdirSync` returning files like `.gitkeep` and filter to `.toml` only. Handled by `.filter(f => f.endsWith('.toml'))`.
- **`dir.pathname` on macOS**: URL `pathname` is the correct way to get the fs path from `AstroIntegrationHook`'s `dir: URL`. Verify it resolves correctly (no trailing slash issues) — use `new URL('.', dir).pathname` pattern if needed.

## Dependencies

None from other TLs. Self-contained to `web/src/scripts/` and `web/astro.config.mjs`.

## Backward Compatibility

No existing pages or routes are modified. Purely additive.
